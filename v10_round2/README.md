# v10 第二轮：更高收益目标的有限研究

用户目标：H在相同口径下超过v9.2，S年化至少30%，同时控制复杂度和过拟合风险。本轮采用 **次日开盘、单边佣金0.01%＋滑点0.10%** 为主验收口径，额外列理想同收盘结果。价格快照统一截止2026-09-11；原v9系列和第一轮`v10_next/`保持不变。

**结果：S达到了历史收益目标；H只有约0.0015个百分点的数值优势，几乎持平，尚无有意义收益提升的证据。理想收盘口径下H没有超过v9.2。**

| 配置 | 净年化 | 最大回撤 | 2022–2025已见验证年化 | 2026截至09-11累计收益 |
|---|---:|---:|---:|---:|
| 同引擎v9.2对照 | 37.02704% | −36.27% | 42.20% | +5.92% |
| 冻结H：去量能＋QVIX＋WLS25/30固定均值 | 37.02857% | −31.26% | 42.52% | −6.40% |
| 冻结S：v9.1底座，WLS30 | 36.10763% | −26.04% | 37.61% | +7.89% |

S不是上一轮的低收益月度组合：它保留原池、牛熊/离场/深跌抄底等规则，只改变排名窗口。±10%窗口的主成本年化约35.75%和35.79%；单边滑点加至0.20%后年化约30.56%。这些支持有限的历史邻域稳定性，**不证明过拟合已经减少，更不保证未来年化30%**。依然保留稀有抄底与原选池偏差。

H在开发期收益最高而被事先选中，但全程优势几乎消失；配对重采样的增量区间跨零。完整列表里的`h_qvix_only`全程约38.66%，它不是本轮开发期选中的版本，不能在看到后段结果后替换为“验证通过的赢家”。该备选的代码和数据全部保留，未被隐藏。

- `registration.json`、`selection.json`和`evaluation.json`记录选择前后时间及代码/数据哈希。各历史区间都已经参与过研究，不是真正未见样本外。
- `profiles.json`固定H/S配置及代码、档案哈希；H仍是未获得可靠增益证据的研究模型，未部署。

从仓库根目录运行：

```bash
python3.8 -B -m v10_round2.cli backtest growth
python3.8 -B -m v10_round2.cli backtest robust
python3.8 -B -m v10_round2.cli signal robust --end 2026-09-11
python3.8 -B -m unittest discover -s v10_round2/tests -v
```

信号入口只读CSV并复算历史模型账户，不获取实时行情，不使用真实持仓，不推送、不下单。返回的日期必须按历史日期理解；支持显式传入新的`--data-dir`，H依赖QVIX时必须同时给`--qvix-file`，避免误把旧快照当实时源。CSV保持无表头`date,adjusted_open,adjusted_close,volume`格式。

```bash
python3.8 -B -m v10_round2.cli signal growth --data-dir /path/to/csv --qvix-file /path/to/qvix.csv --end YYYY-MM-DD
```

开发选择已冻结，`research develop`拒绝覆盖它。`python3.8 -B -m v10_round2.research validate`可在相同代码、数据和保护清单下重新生成派生报告；随后运行`python3.8 -B -m v10_round2.report`。新批次应另建目录并保留此前选择记录，不能删除本批结果后悄悄重选。

## 仍然存在的限制

- 收益门槛是历史筛选条件，未恢复完整历次搜索，因此不报告精确全项目PBO或未来获利概率。减少事件通道、固定平均、参数邻域良好均不能单独证明无过拟合。
- QVIX快照截止09-11前最后一行是09-09，09-10和09-11通道停用；历史发布时间不可验证。未来QVIX缺当日值时同样不会前填。
- 同收盘诊断假设完整收盘信息可按同一收盘价交易，不能用来替代真实成交预期。
- 独立账户候选初始均分、之后份额漂移，不重置、不补仓、不净额省佣金；各账户待成交指令独立保存。
- ETF事后选池、复权修订、盘口/涨跌停成交、资金冲击和整手约束仍未解决。
- 第一轮与旧版本均保留；第二轮没有接入生产。当前较值得后续冻结观察的是S，H不能因为数学上多了极小数值就视为收益升级。
