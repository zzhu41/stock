现有档案缺少覆盖全部候选的同一数据快照、完整逐日收益矩阵、每次查看和修改的完整时间记录；`registry_report.py` 的163+250不能直接用于精确PBO、有效独立试验数或校正后的显著性。即使今后补跑部分矩阵，也必须标注它只是选定候选集的诊断，不能声称恢复了全部研究选择过程。

### 推断与边界

“预注册”局部候选有价值，但如果规则制定前已经查看过这段市场历史和前几轮结果，它仍不构成新的数据样本。第九轮代码甚至把具体2024-09-30→10-08交易列为预期淘汰例子（`v10/lab.py:1298-1302`）；这说明测试设计依赖已知历史。

`v10/freeze_v91.py:24-40,66-70` 当前是固定数据与输出指纹的**代码回归检查**，没有向未来切出收益测试期。指纹一致可证明复现一致，不能证明预测泛化。

## 3. 资产池选择、上市后样本和存活偏差

### 可核查事实

生产池是 `market_data.py:21-35` 手写的7只A股、2只跨境、黄金和货币ETF；没有按历史日期重建全市场基金名单的代码。`pool_test.py:36-41` 明确列出多个精选池，其中一个直接标为“近年强者(后视!)”。`pool_power_set.py:26-35` 穷举全部127个非空A股子集，在同一个2014起历史上评价；跨境两只和黄金固定，因此它没有穷举或排除跨境选择偏差。

`pool_power_result.jsonl:127` 的全7只A股池在127条旧记录中终值最大，`:122` 的去除中证2000池非常接近。这只能说明该次档案的排序；**不能证明原始池一定由这次穷举选出，也不能视为修复后有效的池稳健性结果**。文件没有保存该批的代码/数据指纹和截止日。旧池测试曾存在抄底路径未真正排除标的的问题，当前已修复并增加约束，见 `pool_test_v91.py:12-23`；没有用新引擎重跑并固定快照前，不应继续引用旧127条为有效性能证明。

### 推断与边界

代码正确地没有把新ETF放到其历史数据出现前交易，不能将这里直接判为“预上市价格穿越”。风险来自**在2026年选定具体基金及资产主题，然后把这组存活到今天的标的向历史回看**。仓库未提供基金清盘/合并名单、历史可投资全集、历史流动性门槛或首次选池时未看收益的证据，因此存活偏差和事后资产选择没有被排除；本次也不能量化它们究竟抬高了多少收益。

可以做的历史诊断是固定可执行的逐日纳入规则，补入已退出基金和同期替代品，并把截至当时能获得的数据用于选池。用今天的完整池做LOO只能回答“去掉某一成员会怎样”，不能回答“当时是否能事前选中这些成员”。

## 4. 旧影子记录为什么不足以验证修复后的模型

### 可核查事实

- `signals/shadow_0906.json:1` 与 `signals/shadow_v92.json:1` 均标记开始日2026-09-04、末日09-24，没有 `valuation_version`，两个净值完全相同。
- 两份 `*_trades.csv:2` 各只有一笔同样的09-09从513120切到513100记录。不能从这两笔相同流水中得到新增QVIX或量能通道独立奏效的证据；流水本身也没有通道标签，不能仅凭它严证期间零触发。
- `signals/2026-09-23.txt:2` 显示09-24 14:50生成，却标数据截止09-23；`:24,28` 两个影子读取的是09-23 QVIX。它是原日期错位问题的实际留痕。
- `live_state.py:34-61` 现在要求把旧口径归档并从新信号重新建净值，不能把旧值直接拼到修复后版本；`README.md:112` 已明确这一点。
- `v10/README.md:286-290` 当时承认前向样本为零，却提出2—3次触发复现约69%胜率后再议转正。即便假设独立、真实胜率50%，3次全赢的概率仍为12.5%；更不应忽略事件在同一危机中成簇，以及此前的筛选。

### 推断与边界

旧记录可以作为“当时系统确实产生过这些建议”的前向运维证据，并非时间意义上完全没有价值；但其日期、价格、锁仓和估值规则不同于当前修复后实现，不能用来估计当前模型的执行后收益或证明v9.2新增通道有效。重置日期不能修复旧数据，更不能把已查看过的历史改称新样本外。

两套影子还共享大部分规则、行情、持仓和危机事件；即使以后净值都上涨，也不能简单计为两份相互独立的确认。应直接保存各新增通道的触发、可执行时点、对照持仓和扣费增量收益。

## 5. 目前能下什么结论，下一轮应怎样避免继续污染

**可支持的结论：** 三个版本具有明确的研究者选择偏差风险；v9.2新增层的独立事件证据尤其薄弱。历史参数平台、六起点全赢和失败候选很多，都不足以证明不发生过拟合。规则和数据错误修复后仍应重新评估执行时点、费用及事件集中度，不能沿用旧宣称。

**不能支持的结论：** “这些策略一定是假的”“必然亏损”“过拟合概率为某个精确百分比”，或者“测试过几百个变体，因此每个结果都不可信”。本审计没有估计这样的概率，也没有把所有候选当独立检验。

建议从现在起固定规则、数据定义、执行时间和失败条件，保存代码/输入哈希及不可覆盖的决策快照；每次改规则记录为新研究分支，避免不断重置成功标准。真正新增的未来数据用于预先定义的前向比较；历史滚动训练—测试可做流程诊断，但所有历史已被研究者反复看过时，应明确它不能完全恢复一个原生未见测试集。前向2—3次触发适合检查实现一致性，不能稳定确认约69%的胜率。

## 可复核计数方法

本报告只解析文本和CSV，没有导入旧 `experiments*.py`，因为多个旧脚本在导入时就会联网更新行情（例如 `experiments.py:6`）。结果档案计数可用以下纯读取代码复核：

```python
from pathlib import Path
import json

root = Path("v10/results")
rows, files = [], []
for path in sorted(root.glob("*.jsonl")):
    if path.name == "registry.jsonl":
        continue
    found = [r for r in map(json.loads, path.read_text().splitlines())
             if "variant" in r]
    if found:
        files.append(path.name)
        rows.extend(found)
names = {r["variant"] for r in rows}
controls = {"baseline", "copy_check", "engine_check", "top1_check", "v92_base", "ovchk"}
print(len(files), len(rows), len(names), len(names - controls))
print(len({(r["variant"], r.get("start")) for r in rows}))
registry = list(map(json.loads, (root / "registry.jsonl").read_text().splitlines()))
print(len(registry), sum(r["n_variants"] for r in registry), sum(r["n_jobs"] for r in registry))
```

本次输出为 `26 550 185 179`、`404`、`17 163 342`。这些是文件计数，不是PBO输入中可直接采用的有效独立试验数。
