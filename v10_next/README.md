# v10-H / v10-S：独立、冻结的两条研究路线

本目录完全独立于已有 `strategy.py`、v9/v9.1/v9.2、旧 `v10/`、定时推送和真实账本。使用本次工作区已修复代码的冻结副本，以及本目录内只读行情快照。现有126个受保护文件的哈希保存于 `protected_manifest.json`，研究前后核对。

**交付的是两个可运行的研究版本，不是未来盈利保证。高收益路线本轮未找到信号改进；稳健路线减少规则和换手，但历史表现未优于半仓v9.1对照。** 完整结果含所有失败候选，见 [研究报告](results/REPORT.md)、[CSV](results/summary.csv)及[净值/回撤图](results/equity_drawdown.svg)。

## 两个版本

### v10-H（`growth`）：收益取向，保持已知规则

开发期预定的四个候选是去抄底、去熊市额外7%门槛、WLS20/25/30固定均值、固定成熟核心池。它们没有在预定风险和换手限制内超过v9.1，因此按事先协议回退为v9.1信号逻辑，不因为2022年后数据换选赢家。

- 保留WLS25/VOL20排名、牛熊开关、分池缓冲、急跌/过热离场和原深跌五日锁仓；没有增加QVIX或量能抄底。
- 独立执行器在收盘后生成目标，次日开盘按实际单位数和现金成交。锁仓以确认成交为起点；缺行情时交易延期，后续决策读取实际持仓。
- 这是原信号的独立冻结实现和执行工程迭代，**没有新的信号收益优势声明**。

### v10-S（`robust`）：少规则、分散、低换手

固定五个资产份额：沪深300（510300）、中证500（510500）、纳指（513100）、黄金（518880）、国债（511010），各20%。这不是五个独立风险因子，中国权益占其中两个名额。

1. 每月第一个交易日收盘检查各资产过去244个交易观察期的收益。
2. 收益严格为正，则持有该资产的20%份额；否则该份额持货币ETF（511880）。历史不足的份额也留货币，不补造预上市数据。
3. 次一交易日开盘执行；月内保持单位数，允许权重随价格漂移。

不做横截面追逐第一名，不加抄底、QVIX、成交量恐慌、4%止损、过热门或短周期牛熊门槛。没有月内止损保证；趋势反转仍可能亏损。现金ETF无当日有效报价时，未分配部分保留无息现金，并记录缺失。

## 本次统一回测

区间2014-01-02至2026-09-11，单边佣金0.01%加滑点0.10%；截止日取所有资产共同覆盖日，国债没有更新到09-24。

| 版本 | 全程年化 | 最大回撤 | 年化波动 | 2022–2025已见验证年化 |
|---|---:|---:|---:|---:|
| v10-H（同引擎v9.1对照） | 37.69% | −35.49% | 26.81% | 44.46% |
| v10-S | 10.04% | −23.38% | 10.69% | 8.71% |
| 半仓v9.1＋货币对照 | 20.11% | −19.04% | 13.79% | 22.09% |

稳健版窗口从244变为约220/268时，年化约9.32%/10.34%；单边滑点增加到0.50%时年化约9.16%。这些仅是预定历史敏感性，不能证明未来稳定。降低复杂度不能替代前向验证；半仓对照仍保留原规则及其历史选择偏差。

本轮开发/选择只使用2014–2021；2022–2025之后揭示，2026只报告，未回流调参。**这些历史此前均被项目研究者看过，不是真正独立样本外。** 选择过程、成本和窗口预算见 [PROTOCOL.md](PROTOCOL.md)；七篇原始论文及不可外推边界见 [LITERATURE.md](LITERATURE.md)。

新执行器与旧固定目标重放在2015年两天510500缺行情后产生4个日期的路径差异，且截止日不同。因此不能把本轮37.69%与此前37.13%的差额解释成v10收益改进。原策略同状态决策与冻结副本一致，具体核验见 [legacy_fidelity.json](results/legacy_fidelity.json)。

## 运行

从仓库根目录执行，Python3.8+；回测与信号使用标准库，重新绘图另需Matplotlib。

```bash
python3.8 -B -m v10_next.cli backtest growth
python3.8 -B -m v10_next.cli backtest robust
python3.8 -B -m v10_next.cli signal robust --end 2026-09-11
python3.8 -B -m unittest discover -s v10_next/tests -v
python3.8 -B -m v10_next.verify_legacy
```

`signal`返回带明确日期的**历史模型账户**信号，不读取真实持仓、不联网、不推送、不下单。`None`目标表示保持模型单位数；待执行权重表示之后可成交开盘的目标。默认输入是本目录冻结快照，不会把旧数据伪装成今天的信号。

可以显式提供新的、已完成日线CSV目录，以同一冻结规则做离线复算：

```bash
python3.8 -B -m v10_next.cli backtest robust --data-dir /path/to/dated_csv --end YYYY-MM-DD
python3.8 -B -m v10_next.cli signal growth --data-dir /path/to/dated_csv --end YYYY-MM-DD
```

每个CSV保持项目无表头格式：`date,adjusted_open,adjusted_close,volume`，逐日升序，同一份一致复权历史。目录按版本提供所有必需代码；不自动修改、补抓或拼接数据。`--start`改变起始现金/持仓状态，默认2014起；自定义起点结果不能冒充主报告连续路径。

## 研究复现与冻结

`results/registration.json`在开发运行前写入协议、候选和实现哈希；`selection.json`在后段运行前固定两个ID；`development.json`与`paths.json`保存完整逐日路径。`evaluation.json`保留10个登记项、30个额外成本情景、4个窗口诊断和精确归因，未删除失败项。`profiles.json`固定发布配置和实现哈希，代码被更改时CLI拒绝冒用旧冻结版本。

```bash
# 已有selection时develop会拒绝覆盖，防止看过后段后悄悄重选。
# 若重现开发选择，请复制本目录到单独工作区，保留原结果作为档案。
python3.8 -B -m v10_next.research develop
python3.8 -B -m v10_next.research validate
python3.8 -B -m v10_next.report
```

已有结果可直接重跑`validate`与`report`验证相同实现和数据；重跑会覆盖本目录同名派生报告。需要开发重现时，在另一个仓库副本保存/移开该副本的旧`results/`后再运行，不删除本仓库原始选择档案。

下一步应保持两份配置固定，单独积累带数据时间、信号时间、实际成交和失败记录的新样本；研究信号尚未接入生产。资产池存活/事后选择、复权修订、盘口、涨跌停封单、整手约束和资金规模冲击仍未由这套日线模拟解决。
